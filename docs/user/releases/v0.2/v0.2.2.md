# BetterNAT v0.2.2

Status: AWS gateway replacement-safety patch release. Validate downloaded
artifacts with the attached `SHA256SUMS` file before use.

## What Changed

- Added `eip_allocation_ids`, keyed by availability zone, so independently
  managed AWS EIPs can survive BetterNAT gateway destroy and replacement.
- Added `retain_managed_eips_on_destroy` as a compatibility and migration
  option for existing provider-managed EIPs. Same-name recreation re-adopts a
  uniquely tagged retained address.
- Added bounded retries for AWS launch-template name release after deletion.
- Changed `primary_interface` and `snat_interface` defaults to `auto`; bootstrap
  resolves the Linux interface owning the IPv4 default route while preserving
  explicit overrides.
- Added validation for external EIP availability-zone mappings and duplicate
  allocation IDs.

## Recommended EIP Ownership

For production, manage each public identity as an independent `aws_eip`
resource, normally protected by `prevent_destroy`, and pass its allocation ID
through `eip_allocation_ids`. BetterNAT associates and observes an external EIP
but never releases it.

Use `retain_managed_eips_on_destroy = true` to migrate an existing deployment
without changing its current public IP. Apply the retention setting before
replacing the gateway. The retention setting is an in-place state change;
changing EIP ownership still requires explicit gateway replacement.

## Compatibility

- Provider schema changes are backward-compatible with v0.2.x configurations.
- Existing deployments keep provider-managed EIPs and release them on destroy
  unless retention is explicitly enabled.
- Runtime artifact selection remains separate from the provider package. Keep
  using a supported `betternat_version`, such as `v0.2.1` or `v0.2.0`.

## Known Limitations

- BetterNAT is self-managed and does not provide AWS NAT Gateway equivalent SLA
  semantics.
- Active flows may reset during gateway failover or replacement.
- A retained provider-managed EIP is intentionally left outside Terraform
  state while the gateway resource does not exist. Independent `aws_eip`
  ownership is the recommended steady-state model.
- Published BetterNAT AMIs remain outside this release scope.
