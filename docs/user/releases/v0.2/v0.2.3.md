# BetterNAT v0.2.3

Status: AWS gateway replacement lifecycle safety patch. Validate downloaded
artifacts with the attached `SHA256SUMS` file before use.

## What Changed

- Replacement-required AWS gateway changes are now marked during
  `terraform plan` instead of failing after an in-place apply starts.
- Each physical gateway create receives a `generation_id`; Auto Scaling groups
  and launch templates use generation-scoped names and tags.
- Superseded Terraform and deposed generations cannot refresh themselves from,
  roll back routes for, or clean up a newer active generation.
- A failed create retry receives a fresh generation, avoiding resource-name
  collisions with the failed attempt.
- Launch-template name release uses a bounded ten-minute deadline while still
  retrying only AWS's specific already-exists response.

## Compatibility

- Existing v0.2.x configurations remain valid.
- Existing states retain their legacy resource names until the next physical
  replacement; new creates receive generation-scoped pool names.
- Shared resources keep stable logical names, including externally managed and
  retained provider-managed EIPs.
- Runtime artifact selection remains independent. Supported
  `betternat_version` values remain `v0.2.0` and `v0.2.1`.

## Validation

- `go test ./...`
- `go build ./cmd/terraform-provider-betternat`
- Terraform v1.16.0 local-provider plan smoke
- Lifecycle tests for plan-time replacement, failed-create retry with a fresh
  generation, recovered no-op planning, superseded-generation deletion,
  delayed launch-template release, and retry deadline exhaustion

## Known Limitations

- BetterNAT is self-managed and does not provide AWS NAT Gateway equivalent
  SLA semantics.
- Active flows may reset during gateway failover or replacement.
- This patch prevents generation ownership confusion but does not make
  destroy/create replacement disruption-free.
- Published BetterNAT AMIs remain outside this release scope.
